## 会咬人的几条（都踩过）

- 上游 `songProviderKey()` 对不认识的源**一律回 `'netease'`** → 新源必须包装它，否则徽章/下钻/行标签全错。
- 上游 `renderSongSearchResults` 只画前 `MUSIC_SEARCH_INITIAL_VISIBLE` 行 → 新源那一页**拼在数组末尾就等于看不见**，要用软件自己的 `scoreSongSearchResult` 重排。
- `searchSongResultHtml(s,i)` 返回的是**一整个行 div** → 外挂的面板只能当它的兄弟节点，断言别写 `.search-result .xxx`。
- 沙箱预加载（`sandbox:true`）不能 `require` 磁盘文件，`contextBridge` 暴露的对象会冻结 → 桥接必须内联进 `desktop/preload.js`，且用新名字 `desktopMods`。
- 脚本化搜索要先设 `#search-input.value` 再调 `doSearch(q)`，否则上游那个"输入框与查询词不一致就丢整批"的守卫会得到 0 行，看着像"没结果"。
- 浮窗的 B 站/播客 duration 是**秒**，网易云那类是毫秒；宿主换算成 `qsDurationSec` 再发出去。
- 下钻/返回要给 `requestId` 进位，否则慢回来的回包会盖掉退回后的列表。
- `electron.exe <appdir> --remote-debugging-port` **不开端口**；要用打包布局（`tools/link-runtime.ps1` 硬链接运行时）。
- 夹具必须是 `git archive d43de56` 的**整棵**上游树（只要 desktop/public/server.js 会缺 `qishui-audio-decryptor` 而起不来），且要放在 `.fixture/` 而不是 `tests/`（否则 `node --test tests/` 会把上游自带测试一起跑，报假失败）。
- 别 `taskkill //IM Mineradio.exe`——会连用户自己那份一起杀；按 `$_.Path` 过滤。
- **`audioProxyHeaders` 一 return 就跳过了上游那句 `if (range) headers.Range = range`**。锚点注在函数第一行，所以我们必须自己把 `range` 接过来带上（`server-audio-headers` 那个块现在传的是 `audioProxyHeaders(audioUrl, range)`）。archive.org 上整张专辑的 FLAC 动辄上百 MB，丢 Range = 拖不了进度条、还可能整文件下完才响。
- **`songSourceTagHtml` 里那条三元链只认 NE/QQ/KG/QS/SP**：`class` 走的是 `songProviderKey`（包装过，对的），**文字**却是另一条链，新源会被写成 "NE"。只补 `songProviderKey` 不够，还得包装 `songSourceTagHtml`（`05-sources.js` 里那一颗按上游同一结构自己拼）。
- IA 的一行是 archive.org 的**条目**（常为整张专辑/整场演出），具体播哪个文件由后端按音质档挑；条目级元数据没有时长，真实时长在取址那步才回来。RP 是直播：没有单曲搜索（关键词只排序）、`hasMore` 永远 false、All 档里不掺它。
- **上游原版那个 `queueItemKey` 没有 B 站那一路**：B 站歌掉进 `song:` + id，而同一份分 P 合集里每一段的 id 都是同一个 bvid → 十几段全折叠成一条，点第二首其实还在播第一 P。症状是"队列没多一条 + 当前曲目 cid 是空"，很容易被当成测试自己的问题（这条就是自检抓到才定位到的）。开发仓库在 `09-queue-snapshot-autoplay.js` 加了分支，外挂这里包装同名全局函数（`05-sources.js`）。
- 上游的"清空搜索记录"是**把键写成空列表**（`{"version":1,"items":[]}`）而不是 `removeItem`：自检要数"还剩几条"，量字节会得到 24 字节以为没清干净。
- **`hide` 型的窗口只判存在会让程序退不掉**：浮窗、贴边组件、进度轨都是 `hide` 而不是 `close`。所以 `before-quit` 里必须 `destroy()` 一遍，主窗口关闭时也先把它们收起来。
- **干净实例的 `resources/app` 必须带 `node_modules`**：上游 app 有 5 个运行时依赖（gsap / mpg123-decoder / music-metadata / NeteaseCloudMusicApi / qrcode）。缺了它窗口照样开、后端直接崩，页面永远拿不到桥接 —— 症状是 live-check 第一条等 84 秒然后后面每条再等几十秒，看起来像外挂坏了。`tools/link-runtime.ps1` 现在自己把 `node_modules` 链接进来。
- `live-check` 里那些送给页面的表达式是模板字符串，少一个右括号要**跑到那条断言才炸**（一趟八九分钟）。改完先跑 `node tools/check-page-expressions.mjs`，两秒钟把 88 条全解析一遍。
